# feeling-relay

[English version](README.md) · [Участие в проекте](CONTRIBUTING.ru.md) · [GPL-2.0-only](LICENSE)

Rust workspace для предоставления Linux измерений и событий сенсорного
сопроцессора Qualcomm.

## Пакет для Arch Linux

Соберите оба пакета из текущей рабочей копии.

```sh
tar --transform='s,^,feeling-relay-0.1.0/,' -czf feeling-relay-0.1.0.tar.gz \
    Cargo.toml Cargo.lock crates kernel systemd LICENSE README.md README.ru.md
makepkg -s
```

`feeling-relay` устанавливает демон и юнит systemd.
`feeling-relay-dkms` поставляет исходники модуля IIO. Для DKMS нужны
заголовки целевого ядра. Модуль загружается отдельно.

При первом запуске `feeling-relay.service` создаёт
`/etc/feeling-relay/feeling-relay.toml` с комментариями. Настройте профиль,
задайте `enabled = true` и запустите или включите службу. Пока шаблон
отключён, демон штатно завершает работу. Существующие профили без
ключа `enabled` считаются включёнными.

## Порты сенсоров

`feelrel-ports` определяет порты акселерометра, гироскопа, магнитометра, чехла и жестов. Угловая скорость выражается в рад/с, магнитное поле — в мкТл.
Ускорение выражается в м/с² в системе координат сенсора. Для чехла
доступны последнее известное состояние и отдельный поток изменений.
Пробуждение и наклон представлены отдельными событиями.

Чтение порта не ждёт следующего события. `Ok(None)` означает, что очередь
пуста или источник ещё не сообщил состояние чехла. Таймстампы
монотонны в пределах часов источника. Для сравнения показаний от
источников с разными часами нужна синхронизация.

## Источник SLPI

`SlpiAdapter` обслуживает подписки через один сокет QRTR. Укажите имена
каналов, частоту акселерометра и частоту часов SLPI в `SlpiProfile`.
Ожидайте `pump()` в Tokio с включёнными I/O и таймерами и считывайте
данные из соответствующих портов. Если потребитель отстал, при следующем
чтении очередь сообщит число потерянных событий.

## Ввод Linux

`feelrel-linux-adapter` публикует состояние чехла как `EV_SW / SW_LID`,
а жесты — как `EV_MSC / MSC_GESTURE`. Для пробуждения и наклона задайте
разные положительные коды и укажите те же значения у потребителей.
Обоим устройствам нужен доступ к `/dev/uinput`. Таймстампы выставляет ядро.

## Запуск демона

Запустите `feeling-relay [profile.toml]` в Linux с доступом к QRTR и
`/dev/uinput`. В профиле задаются параметры подписок SLPI, имена
виртуальных устройств и коды жестов.

Демон восстанавливает подписки после исчезновения сервиса QRTR или
пропажи отсчётов акселерометра. `sample_timeout_ms` по умолчанию
равен 5000 мс и должен превышать ожидаемый интервал между отсчётами.

## Linux IIO

Соберите модуль под целевое ядро командой
`make -C /path/to/kernel/build M="$PWD/kernel" modules`. Ядру нужен
`CONFIG_IIO`. Загрузите `feelrel_iio` и задайте
`iio_accelerometer_device = "/dev/feelrel-iio-accel"` на верхнем уровне
профиля демона, чтобы включить публикацию акселерометра.

Устройство `feelrel-accelerometer` отдаёт последний отсчёт через
`in_accel_{x,y,z}_raw` с общим масштабом `0.000001` м/с² на единицу.
До первого отсчёта и после отключения отправителя данные недоступны.
Интерфейс прямого чтения выдаёт отсчёты без буфера и таймстампов.

Для гироскопа и магнитометра добавьте секции `[slpi.gyroscope]` и
`[slpi.magnetometer]` с полями `channel` и `hz`. Ключи верхнего уровня
`iio_gyroscope_device = "/dev/feelrel-iio-gyro"` и
`iio_magnetometer_device = "/dev/feelrel-iio-magn"` включают прямое
чтение в IIO. В IIO угловая скорость выражается в рад/с, магнитное поле
— в гауссах.

В необязательной секции `[slpi.measurements]` задаются каналы
освещённости, RGB, гравитации, трёх видов кватернионов, ориентации,
шагомера, значительного движения и PSMD. Для непрерывных каналов задаются
имя и частота, для состояний и событий достаточно имени.
После загрузки модуля включите `iio_measurements_directory = "/dev"`
для публикации дополнительных измерений и ориентации. События движения
используют коды `MSC_GESTURE` из `[input.motion]`.

Два режима PSMD используют отдельные соединения QRTR, поскольку прошивка
присылает одинаковый пустой отчёт о движении и покое. При восстановлении
связи демон пересоздаёт обе подписки вместе с остальными.

Обязательная секция `[slpi.reports]` описывает отчёты SNS выбранной
прошивки. Для векторных данных задаются номер сообщения, номер поля
protobuf и порядок значений с индексами от нуля. Необязательный массив
`scales` переводит отдельные значения в единицы портов. Для чехла,
ориентации и шагомера задаются целочисленные поля и допустимые значения
или номера сообщений. Коды отчётов жестов и режимов PSMD также задаются
профилем.
